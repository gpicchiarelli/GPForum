# I18N

`GPForum::Service::I18N` remains the public facade for locale negotiation,
catalogs, pluralization, locale metadata, and date/time/number formatting.

Runtime ownership:

- `GPForum::Service::I18N::Catalog` owns catalog data, lookup, and
  `{name}` interpolation, and reads the catalogs from `locale/*.po` with
  `GPForum::Service::I18N::PoFile`;
- `GPForum::Service::I18N::Locale` owns Accept-Language negotiation and
  locale metadata;
- `GPForum::Service::I18N::Formatter` owns date, time, datetime, and number
  formatting.

Supported foundation locales, one per catalog in `locale/`:

- `en`;
- `it`.

Locale resolution order:

1. authenticated session preference;
2. guest locale cookie;
3. `Accept-Language`;
4. configured default locale;
5. safe fallback to `en`.

Authenticated users can update locale from `/settings`; guests keep using the
SSR shell selector and `gpforum_locale` cookie from `Web::IdentityAccess`.
HTML selector writes set a success flash and redirect to `return_to`. The
settings form posts through
the same persistence path as the shell selector, so login/logout does not reset
the selected locale.

Templates use `t()`, `l()`, `tc()`, `ui_label()`, and formatting helpers such as
`ui_date`, `ui_time`, `ui_datetime`, and `ui_number`. User-generated content,
slugs, and canonical database values are not translated. Canonical values are
translated only at the presentation layer.

## Catalogs

The messages are GNU gettext PO files, one per locale and named after it:
`locale/en.po` and `locale/it.po`. Each is UTF-8 and opens with a header that
names its `Language` and declares `Plural-Forms: nplurals=2; plural=(n != 1);`.
An entry is one message:

```
#, python-brace-format
msgctxt "auth.signed_in_as"
msgid "Signed in as {user_id}"
msgstr "Accesso come {user_id}"
```

- `msgctxt` is the key the code asks for: `t('auth.signed_in_as')`.
- `msgid` is the English text, the same in every file, so a translator always
  sees what is being translated.
- `msgstr` is what a reader of the locale sees. In `en.po` it is the `msgid`
  again.
- `#, python-brace-format` marks a message with `{name}` placeholders. It is
  gettext's name for that syntax; with it, `msgfmt --check`, Poedit and
  Weblate refuse a translation that drops or renames a placeholder.
- A message the code counts -- `tc()` in a template, and the relative-time
  phrases -- is a plural entry: `msgid_plural` after the `msgid`, then
  `msgstr[0]`, said of one, and `msgstr[1]`, said of any other count, zero
  included:

  ```
  #, python-brace-format
  msgctxt "notifications.unread_count"
  msgid "{count} unread"
  msgid_plural "{count} unread"
  msgstr[0] "{count} non letta"
  msgstr[1] "{count} non lette"
  ```

- `# Same as English.` above an entry says that its translation reads as the
  English on purpose ("Admin", "Email"), so it is not taken for one left
  untranslated.

`GPForum::Service::I18N::Catalog` reads the files once, when it is loaded --
in Hypnotoad's manager, before the workers fork -- into the same in-memory
catalog the code has always asked. The reader, `GPForum::Service::I18N::PoFile`,
is part of the project rather than a CPAN dependency: it accepts what gettext's
tools write and refuses anything else, naming the file and line. A malformed
catalog stops the application at startup rather than serving keys. An edited
`.po` file is therefore read at the next restart or hot deploy, and should pass
the checks below before it gets there.

A locale lacks a message its file leaves out, leaves untranslated (an empty
`msgstr`) or marks `fuzzy`, as gettext would not show those either. The page
then shows the English, and the `missing_key_logger` logs the fallback
(`reason => 'fallback'`); a key that English lacks too is shown as the key
itself (`reason => 'missing'`).

## Translator workflow

The tools are GNU gettext's (`brew install gettext` on macOS, the `gettext`
package elsewhere) and any PO editor: Poedit, Lokalize, Weblate, or a text
editor. Run them under a UTF-8 locale (`export LC_ALL=en_US.UTF-8`), or
`msgfilter` warns that its output may be wrong.

### Adding, changing or removing a message

A developer adds a message to `locale/en.po`, in key order, with the English
as both `msgid` and `msgstr`, and the flag or the plural form above when it
needs them. A change to the English edits both; a message the code no longer
asks for is deleted. Then every other locale is brought up to date from a
template of the English, made on the fly:

```
msgfilter --keep-header --input=locale/en.po --output-file=/tmp/gpforum.pot true
msgmerge --update --previous --backup=none locale/it.po /tmp/gpforum.pot
msgattrib --no-obsolete --output-file=locale/it.po locale/it.po
```

- `msgfilter ... true` empties every `msgstr`, so the template carries the
  English only as `msgid`. Merged straight from `en.po`, a new message would
  arrive in `it.po` already "translated" as its English.
- `msgmerge` adds a new message with an empty `msgstr` (or, when it resembles
  an existing one, with that one's translation marked `fuzzy`), marks `fuzzy`
  a message whose English changed, keeping the old English in `#|` lines, and
  turns a removed one into an obsolete `#~` entry.
- `msgattrib --no-obsolete` drops the obsolete entries. The loader would skip
  them, but nobody needs them in the file.

The tools write the files in the layout they are already in, so the diff is
the change and nothing else.

### Translating

The translator opens `locale/it.po` and, for each message with an empty
`msgstr` or the `fuzzy` flag:

- writes the translation, keeping every `{placeholder}` of the English. The
  singular, `msgstr[0]`, may leave `{count}` out: "un giorno fa";
- for a fuzzy message, checks the translation against the new English (the
  old English is in the `#|` lines), then deletes the `fuzzy` flag and the
  `#|` lines;
- puts `# Same as English.` above a message whose translation is the English
  itself, and takes it off one whose translation no longer is: `msgmerge`
  keeps a translator's comment when the English changes.

`msgattrib --untranslated locale/it.po` and
`msgattrib --only-fuzzy locale/it.po` list what is left. Until it is done,
those messages are shown in English, and each fallback is logged.

### Checking

```
msgfmt --check --statistics --output-file=/dev/null locale/it.po
script/gpforum-carton exec prove -l t/295-i18n-po-catalogs.t t/297-i18n-po-reader.t t/64-i18n.t
```

`t/295-i18n-po-catalogs.t` is the gate. It checks that:

- the catalogs are what the PO files hold, and no message is left in the
  module;
- each file has the header gettext expects, and gives each message one key,
  once;
- every locale has every key `en.po` has, and no other, translated (none empty
  or fuzzy) from the current English;
- a translation that reads as the English carries `# Same as English.`, and
  `en.po` shows its `msgid`;
- every placeholder of the English is kept in each translation, and each
  message with placeholders is flagged `python-brace-format`;
- a message is plural exactly where the code counts it, and `msgstr[0]` is
  what a count of one reads, `msgstr[1]` any other;
- `msgfmt --check` accepts each file (skipped when gettext is not installed).

`t/297-i18n-po-reader.t` covers the reader and the loader, malformed files
included.

### Adding a locale

The new file starts from the template of the English, made as above:

```
msgfilter --keep-header --input=locale/en.po --output-file=/tmp/gpforum.pot true
msginit --no-translator --locale=de --input=/tmp/gpforum.pot --output-file=locale/de.po
```

Every file in `locale/` is a supported locale -- negotiated from
`Accept-Language` and offered by the selector -- from the next start,
translated or not. So the new file is merged only together with the rest:

- its translation, as above (`t/295-i18n-po-catalogs.t` fails until every
  message has one);
- its name, direction, and date and number formats in
  `GPForum::Service::I18N::Locale`. Without them it is described and
  formatted as English;
- a migration that adds it to `users_preferred_locale_check`, the constraint
  on `users.preferred_locale`, which migration 019 limits to `en` and `it`.
  Without it a member's choice of the locale cannot be saved;
- the locale in the lists `t/64-i18n.t` and `t/295-i18n-po-catalogs.t`
  expect.

Its header must declare `Plural-Forms: nplurals=2; plural=(n != 1);`, the rule
of English, Italian, German or Spanish, because the formatter knows only the
`one` and `other` categories. `msginit` writes the language's own rule and the
loader refuses any other, so French (`plural=(n > 1)`) or Polish (three forms)
needs the formatter's plural categories first.

## Relative times

A forum timestamp -- the category list, search results, bookmarks, the feed
and the notification inbox -- is rendered, server-side and without
JavaScript, by the `components/timestamp` partial:

```
<%= include 'components/timestamp', at => $thread->{last_activity_at},
  missing => t('state.unknown') %>
```

It writes one element:

```
<time datetime="2026-05-23T12:00:00Z" title="2026-05-23 14:00 CEST">3 minutes ago</time>
```

- `datetime` is the instant in UTC (`Formatter::iso8601`). PostgreSQL's
  rendering, `2026-05-23 12:00:00+00`, is not a valid HTML datetime (the
  offset has no minutes), so it is never written there as it comes.
- `title` is the absolute time in the reader's locale and time zone, naming
  the zone: a signed-in member's own zone, otherwise
  `GPFORUM_DEFAULT_TIMEZONE`. An anonymous page is always in the forum's
  zone, even when the session still holds a member's (one that has just run
  out or been revoked is signed out at the door, but keeps its preferences
  for that request): the page cache keys by locale and theme, not by zone.
  It shows on hover and is read by assistive technology, so the exact time is
  always one step away.
- The text, for a signed-in reader, is a phrase for a recent time and the date
  after that. `Formatter::relative_datetime` picks it by elapsed time, rounded
  down to whole units, which is the same in every zone:

  | Age | Phrase (`en` / `it`) |
  | --- | --- |
  | under a minute, or up to a minute ahead (clock skew) | just now / adesso |
  | 1 minute | a minute ago / un minuto fa |
  | 2 to 59 minutes | N minutes ago / N minuti fa |
  | 1 hour | an hour ago / un’ora fa |
  | 2 to 23 hours | N hours ago / N ore fa |
  | 1 day | a day ago / un giorno fa |
  | 2 to 6 days | N days ago / N giorni fa |
  | 7 days or more, or more than a minute ahead | the date, in the reader's zone |

  The phrases are the `common.time_*` keys, with `one` and `other` forms in
  every locale. A label before a timestamp is written to suit both a phrase
  and a date: "Saved: 3 minutes ago", "Last activity: 2026-05-23".

- With no timestamp the partial prints `missing`; with one the formatter
  cannot read, it prints the value as it is rather than a made-up time.

### Relative times and the page cache

An anonymous reader sees the absolute time as the text (and in `title`); only
a signed-in reader sees the phrase. This is decided by the same test the
public page cache uses (`Web::PublicCacheAccess`: signed in or not), and it is
deliberate:

- An anonymous page may be served from the public page cache for up to
  `GPFORUM_CATEGORY_CACHE_TTL_SECONDS` (60 by default), and is sent with
  `Cache-Control: public, max-age=TTL, stale-while-revalidate=TTL`, so a
  browser or proxy may keep it up to two TTLs more. A phrase rendered into it
  could be wrong by three TTLs -- "just now" for a three-minute-old post with
  the defaults. Rounding the phrases to the TTL would make them coarse for
  everyone and still not bound what a downstream cache does.
- A phrase changes the page every minute, so the page's `ETag` (a hash of
  the body) would change with it and a client revalidating with
  `If-None-Match` would get the whole page again instead of a 304. (Today the
  CSRF token in the page's language and theme forms is minted per render, so
  the `ETag` already changes from one render to the next; the phrase would
  keep it changing once that is fixed.)
- The absolute time does not depend on the clock, so the cached page is never
  stale for it, however long it is kept.

A signed-in page is rendered for its reader on each request and is not
cached, so its phrase is true when it is sent. `t/281-relative-times.t`
checks both sides, including that an anonymous page rendered an hour later is
the same page, and that a lapsed member's page goes into the cache in the
forum's zone.

Other pages -- the home page, profiles, mentions, and the admin, moderation
and privacy screens -- still print the absolute time with `dt()`.

`t/64-i18n.t` checks catalog coverage, missing-key behavior, fallback logging,
namespace discipline, Accept-Language negotiation, and localized SSR shell
rendering. `t/117-i18n-boundaries.t` covers the catalog, locale, and formatter
helpers without loading the web app. `t/187-locale-formatting.t` covers the
formatter's dates, zones and numbers, and the relative-time boundaries and
phrases in every locale. `t/295-i18n-po-catalogs.t` and
`t/297-i18n-po-reader.t` cover the PO catalogs, as described under
[Checking](#checking). New template-visible strings should be added to
`locale/en.po` and translated in `locale/it.po` before the template uses them.
