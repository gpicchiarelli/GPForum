# I18N

`GPForum::Service::I18N` remains the public facade for locale negotiation,
catalogs, pluralization, locale metadata, and date/time/number formatting.

Runtime ownership:

- `GPForum::Service::I18N::Catalog` owns catalog data, lookup, and
  `{name}` interpolation;
- `GPForum::Service::I18N::Locale` owns Accept-Language negotiation and
  locale metadata;
- `GPForum::Service::I18N::Formatter` owns date, time, datetime, and number
  formatting.

Supported foundation locales:

- `en`;
- `it`.

Locale resolution order:

1. authenticated session preference;
2. guest locale cookie;
3. `Accept-Language`;
4. configured default locale;
5. safe fallback to `en`.

Authenticated users can update locale from `/settings`; guests keep using the
SSR shell selector and `gpforum_locale` cookie from `Web::IdentityAccess`.
HTML selector writes set a success flash and redirect to `return_to`. The
settings form posts through
the same persistence path as the shell selector, so login/logout does not reset
the selected locale.

Templates use `t()`, `l()`, `tc()`, `ui_label()`, and formatting helpers such as
`ui_date`, `ui_time`, `ui_datetime`, and `ui_number`. User-generated content,
slugs, and canonical database values are not translated. Canonical values are
translated only at the presentation layer.

## Relative times

A forum timestamp -- the category list, search results, bookmarks, the feed
and the notification inbox -- is rendered, server-side and without
JavaScript, by the `components/timestamp` partial:

```
<%= include 'components/timestamp', at => $thread->{last_activity_at},
  missing => t('state.unknown') %>
```

It writes one element:

```
<time datetime="2026-05-23T12:00:00Z" title="2026-05-23 14:00 CEST">3 minutes ago</time>
```

- `datetime` is the instant in UTC (`Formatter::iso8601`). PostgreSQL's
  rendering, `2026-05-23 12:00:00+00`, is not a valid HTML datetime (the
  offset has no minutes), so it is never written there as it comes.
- `title` is the absolute time in the reader's locale and time zone, naming
  the zone: a signed-in member's own zone, otherwise
  `GPFORUM_DEFAULT_TIMEZONE`. An anonymous page is always in the forum's
  zone, even when the session still holds a member's (one that has just run
  out or been revoked is signed out at the door, but keeps its preferences
  for that request): the page cache keys by locale and theme, not by zone.
  It shows on hover and is read by assistive technology, so the exact time is
  always one step away.
- The text, for a signed-in reader, is a phrase for a recent time and the date
  after that. `Formatter::relative_datetime` picks it by elapsed time, rounded
  down to whole units, which is the same in every zone:

  | Age | Phrase (`en` / `it`) |
  | --- | --- |
  | under a minute, or up to a minute ahead (clock skew) | just now / adesso |
  | 1 minute | a minute ago / un minuto fa |
  | 2 to 59 minutes | N minutes ago / N minuti fa |
  | 1 hour | an hour ago / un’ora fa |
  | 2 to 23 hours | N hours ago / N ore fa |
  | 1 day | a day ago / un giorno fa |
  | 2 to 6 days | N days ago / N giorni fa |
  | 7 days or more, or more than a minute ahead | the date, in the reader's zone |

  The phrases are the `common.time_*` keys, with `one` and `other` forms in
  every locale. A label before a timestamp is written to suit both a phrase
  and a date: "Saved: 3 minutes ago", "Last activity: 2026-05-23".

- With no timestamp the partial prints `missing`; with one the formatter
  cannot read, it prints the value as it is rather than a made-up time.

### Relative times and the page cache

An anonymous reader sees the absolute time as the text (and in `title`); only
a signed-in reader sees the phrase. This is decided by the same test the
public page cache uses (`Web::PublicCacheAccess`: signed in or not), and it is
deliberate:

- An anonymous page may be served from the public page cache for up to
  `GPFORUM_CATEGORY_CACHE_TTL_SECONDS` (60 by default), and is sent with
  `Cache-Control: public, max-age=TTL, stale-while-revalidate=TTL`, so a
  browser or proxy may keep it up to two TTLs more. A phrase rendered into it
  could be wrong by three TTLs -- "just now" for a three-minute-old post with
  the defaults. Rounding the phrases to the TTL would make them coarse for
  everyone and still not bound what a downstream cache does.
- A phrase changes the page every minute, so the page's `ETag` (a hash of
  the body) would change with it and a client revalidating with
  `If-None-Match` would get the whole page again instead of a 304. (Today the
  CSRF token in the page's language and theme forms is minted per render, so
  the `ETag` already changes from one render to the next; the phrase would
  keep it changing once that is fixed.)
- The absolute time does not depend on the clock, so the cached page is never
  stale for it, however long it is kept.

A signed-in page is rendered for its reader on each request and is not
cached, so its phrase is true when it is sent. `t/281-relative-times.t`
checks both sides, including that an anonymous page rendered an hour later is
the same page, and that a lapsed member's page goes into the cache in the
forum's zone.

Other pages -- the home page, profiles, mentions, and the admin, moderation
and privacy screens -- still print the absolute time with `dt()`.

`t/64-i18n.t` checks catalog coverage, missing-key behavior, fallback logging,
namespace discipline, Accept-Language negotiation, and localized SSR shell
rendering. `t/117-i18n-boundaries.t` covers the catalog, locale, and formatter
helpers without loading the web app. `t/187-locale-formatting.t` covers the
formatter's dates, zones and numbers, and the relative-time boundaries and
phrases in every locale. New template-visible strings should be added to both
English and Italian catalogs before the template uses them.
